# Oblig demo script / walkthrough

**Audience:** fintech founders, CIOs/CTOs, IT leads, or partners (e.g. consulting / country managers)  
**Length:** ~20–25 minutes + 5–10 min Q&A  
**Goal:** Show *current tech-governance posture* in minutes, then how that turns into policies, gaps, and FI-ready answers — not a six-month GRC project.

---

## 0. Setup (before the call)

- [ ] Live site: `https://oblig.vercel.app` (or staging)
- [ ] Demo account signed in (or ready to sign up live)
- [ ] Optional: one assessment partially filled so dashboard isn’t empty
- [ ] Browser: zoom 110%, close extra tabs
- [ ] Backup: 3–4 screenshots if network fails

**One-line open:**

> Oblig is a technology governance platform for APAC fintechs — tech risk, data, and AI — so you know your posture for leadership *and* for selling into banks and other regulated FIs.

---

## 1. Context (2 min) — don’t open the product yet

**Say:**

> If you sell into banks, insurers, or payment institutions in Singapore, Malaysia, and the rest of APAC, you don’t get asked for SOC 2 alone. You get questionnaires shaped by **MAS TRM, BNM RMiT**, outsourcing rules, data location, and increasingly **AI**.

> ISO helps as a baseline. It doesn’t define MAS notification culture, BNM testing baselines, or residency answers by market.

> Oblig does three things: **measure posture**, **close gaps with drafts and a roadmap**, and **stay oriented to the frameworks those buyers actually use**.

**Pause:** “Does that match what you’re seeing with banks or internal audits?”

---

## 2. Homepage / positioning (1–2 min)

**Show:** Hero — *Your Tech Governance / scored and ready to act on*

**Point out:**

- For fintechs building their own bar **and** those selling into FIs
- Trust chips: time, markets, *Updated as APAC guidance moves*
- Optional: Pricing or Docs only if they ask

**Don’t:** Read the whole page. Click **Get my posture score** / assessment CTA.

---

## 3. Assessment (5–6 min) — core of the demo

**Show:** `/app/assessment`

**Say:**

> This is a structured checklist across governance domains — oversight, vendors, monitoring, data, incidents, AI, and so on. Self-reported, on the order of minutes for a first pass.

**Do:**

1. Open 1–2 sections (e.g. **Board & oversight**, **Vendor due diligence**).
2. Check 2–3 items; explain *why* (buyer/regulator angle in the helper text).
3. Show progress / score movement if visible.
4. Mention: sign-in saves across devices; anonymous can stay in browser.

**Line for partners:**

> A country manager or CIO can run this with the tech lead in one sitting and leave with a shared baseline — not a binder.

---

## 4. Dashboard (2–3 min)

**Show:** `/app` dashboard

**Say:**

> Once you’ve assessed, leadership sees score, maturity band, and open risks — without opening ten tools.

**Point to:**

- Overall readiness
- Category / market-oriented signals if shown
- Open risks or AI-style recommendations if present

**Bridge:** “From here we don’t stop at a score — we produce artefacts.”

---

## 5. Tech Governance Policies (3–4 min) — high demo value

**Show:** `/app/policies` → **Generate Policy**

**Do:**

1. Generate **Vendor & Third-Party Risk Management** *or* **Incident Notification**.
2. Open the draft: Purpose, Roles, Requirements, framework note.
3. Scroll to one concrete requirement (e.g. annual re-assessment, MFA, data location register).
4. Note: editable draft, export path — *not legal advice; counsel reviews before external use*.

**Say:**

> Twelve templates built for APAC tech-governance themes — vendor risk, residency, incidents, AI, cloud, access, SDLC, logging — not a blank Word doc.

---

## 6. Copilot (2–3 min)

**Show:** `/app/copilot`

**Ask (example):**

> What should we prioritise if we’re selling into Singapore and Malaysia first?

**Or:**

> How does ISO 27001 relate to our checklist?

**Say:**

> When you’re signed in, it can use readiness context. It’s a specialist for APAC tech/data/AI governance — not a general chatbot.

**If API is slow:** Use the offline ISO or prioritisation-style answers you already have.

---

## 7. Compliance mapping (2 min)

**Show:** `/app/compliance`

**Say:**

> Coverage views against APAC technology/vendor and AI frameworks — so the conversation is “where are we vs MAS/BNM-shaped expectations,” not only “we have a certificate.”

**Be honest if asked about VN/TH:**

> We position ten markets; the deepest control maps are on the core set, with Vietnam and Thailand expanding.

---

## 8. Optional extras (if time / interest)

| Module | One line |
|--------|----------|
| **Risk** | Track likelihood, impact, owner, treatment |
| **Roadmap** | Phased plan from current posture |
| **Questionnaire** | Draft answers from assessment + policies on file |
| **Docs** | Getting started, glossary, MAS/BNM deep dives, APAC vs EMEA |

Skip Evidence/Reports deep-dive unless they care about audit packs.

---

## 9. Close (2 min)

**Recap:**

1. Measure posture in minutes
2. Turn gaps into **policies + priorities**
3. Stay oriented to **APAC tech governance** (with ongoing regulatory monitoring behind the scenes)

**Commercial honesty (if relevant):**

> We’re in focused rollout — ideal for teams who want a working baseline now. Billing and team features are expanding; happy to set up a design-partner arrangement.

**Ask:**

> If you ran this with one FI target market in mind, which market and which gap would you want to close first?

**CTA options:**

- They complete the assessment after the call
- You send magic link + 30-min follow-up
- Intro to a fintech client for a joint session

## Objection cheat-sheet

| They say | You say |
|----------|---------|
| “We already have ISO/SOC 2.” | “Keep it — Oblig maps the APAC-specific layer questionnaires still ask for.” |
| “Is this legal advice / certification?” | “No. Informational mapping and drafts; counsel and the buyer’s actual requirements win.” |
| “We’re not selling to banks.” | “Still useful for board/CIO posture on tech, data, and AI — FI sales is one path, not the only one.” |
| “Can it do DORA / EU?” | “We’re APAC-first. EU resilience is a different rulebook; we explain that in docs.” |
| “How current is content?” | “Framework docs and a weekly tech/data/AI intel sweep; product changes go through human review.” |
